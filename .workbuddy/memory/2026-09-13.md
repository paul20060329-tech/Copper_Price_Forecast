## 需求：演示要「运行代码」而非双击 exe
- 用户澄清真实场景：给别人电脑配好、用于现场**演示**，要「敲核心代码」，
  不能直接双击 exe（黑盒）。诉求=写一个**指向 exe 的代码入口**：运行代码 → 代码调用 exe 完成计算。
- 关键点：演示电脑通常没有 torch/pandas 环境 → 入口脚本必须只依赖标准库；
  exe 内嵌 Python 环境，真正计算交给 exe。

## 交付
- 新增 `run_demo.py`（仓库根）：演示入口，仅用 os/sys/time/subprocess。
  - 顶部「演示输入区」：OPEN_BROWSER / RAW_METRICS / HEADLESS / EXTRA_ARGS，现场可改。
  - 支持命令行透传（sys.argv[1:] 原样交给 exe，如 --nogui / --raw / --noopen）。
  - find_exe() 依次找 dist/、同级、CopperPriceForecast/ 下的 CopperPriceForecast.exe。
  - 打印 4 步流水线讲解 + 调用引擎 + 回显退出码与面板路径。
- 新增 `run_demo.bat`（根）：Windows 原生零安装版（演示电脑完全无 Python 时用），
  chcp 65001；注意 echo 里 `<` 要写成 `^<`、`%` 写成 `%%`。
- README 第三节重构：方式 A=代码入口演示（run_demo.py / run_demo.bat），方式 B=直接双击 exe，
  方式 C=源码运行（仅开发者）；并清理了上一轮遗留的重复段落；项目结构补入两个入口文件。

## 验证
- `python run_demo.py --nogui --noopen`（受管 Python 3.13.12）→ EXIT=0，
  生成 dist/output/copper_dashboard.html（1,165,366 B）。链路打通。
- 注意：PowerShell 的 `&` 不等待 GUI 子系统进程；验证生成产物时要靠 python subprocess.call（会等待）
  或 Get-Process + WaitForExit 轮询。PowerShell 工具不回显 stdout，需写文件再读。
