# 2026-09-16 工作日志（续）

## 修复：五大地区专属预测图「二次进入没有动画」

### 现象
用户反馈：滚动到五大地区图时，只有第一次进入有生长动画，之后每次进入都是静止画面。

### 排查路径（层层剥离，每层都实测证伪）
1. **先怀疑 `growCharts` 实现无效** —— 原实现只做 `setOption({animation:true})` + `resize()`。
   用 rAF 逐帧采集 canvas 指纹做判据（关键检测手段，见下），确认方案确实无效。
2. **做最小复现定位 ECharts 机制**（`min_repro.html`）：
   - 首次 `setOption(true, {notMerge:true})` → 动画播放 ✓
   - 二次同样调用 → **静止 ✗**
   - 结论：ECharts 5 对同一实例再次提交相同结构的 option 时判定为
     **update 而非 init**，走 `animationDurationUpdate` 分支，折线图几乎无可见动画。
   - 实测解法：**先 `ch.clear()` 再 `setOption`**，强制走完整 init 路径，
     可无限次重播（验证 C/D/F 三组全部通过）。
3. **应用 clear 方案后仍不重播** → 继续查触发链，发现 **IntersectionObserver 阈值不可达**：
   - `#mgrid` 高约 1270px，整页总高仅 3399px，视口 900px。
   - 滚到页面底部时 `mgrid.bottom ≈ +290px`，**它永远无法完全离开视口**，
     `threshold:0` 的「完全离开」条件不可达。
   - 改用可见比例阈值后发现问题更根本：**主 `io` 的 `threshold:.14` 观察的是外层
     `section.rv`（高约 1360px），滚到底时该 section 可见比例仍有 0.29，
     始终高于 0.14，因此 IO 永远不会因跨越 .14 而再次回调，
     主 `io` 里的 `growCharts()` 在二次进入时根本不会执行。**
     —— 这正是「复位了但不再重播」的根因。
4. **另有定时器交错隐患**：`growCharts`/`resetCharts` 各挂一批错峰 `setTimeout`，
   快速滚动时复位回调可能在生长回调之后执行，用 `animation:false` 覆盖掉刚设的
   `animation:true`。

### 最终修法
1. **抽出 `chartOption(r, idx, anim)`** 纯配置函数；`anim` 控制入场动画开关。
2. **`applyCharts(anim, stagger)`** 统一管理 5 张图的错峰重绘，
   执行前先 `clearTimeout` 上一批未执行定时器（`chartTimers` 数组），消除交错。
3. **重构为「重播总线」**：新增 `watch(el, inRatio, onEnter, onLeave)`，
   直接观察 `#mgrid` 与 `#console` 自身，同时承担复位与重播：
   - `#mgrid`：比例 ≥0.6 → 建图或重播生长；<0.6 → 转静态终态
   - `#console`：比例 ≥0.3 → 打字或重播；<0.3 → 回 standby
   - 两个元素尺寸差异大，**必须用各自的阈值**：
     `#mgrid` 首屏比例约 0.63、滚到底降到 0.23~0.35；
     `#console` 首屏比例仅约 0.40（若用 0.6 会被误判为「离开」而不启动）。
4. 主 `io` 中移除 `#mgrid` 分支（保留 `#console` 启动），避免双重驱动。

### 验证方法（可复用，重要）
**用 rAF 逐帧采集 canvas 指纹判据动画是否真在播**：
```js
window.__FP = [];
const el = document.getElementById('rc0');
const tick = () => {
  const c = el && el.querySelector('canvas');
  if (c) window.__FP.push(c.toDataURL().slice(-64));
  if (window.__FP.length < 100) requestAnimationFrame(tick);
};
requestAnimationFrame(tick);
// 采样结束后：new Set(window.__FP).size > 8 即判定动画在播放
```
注意坑：**必须在触发动作的同一时刻开始采样**，且采样间隔要远小于动画时长。
早期用「外部 waitForTimeout 后再采样」的方法有严重时序缺陷，
会把已播完动画误判为「静止」（这是本次排查绕弯的主要原因）。

### 最终验证结果
- 图表动画 **5/5 轮全部重播**：97 / 80 / 77 / 88 / 79 个不同帧
- 控制台：首入打字 ✓ / 离屏复位为 standby ✓ / 重入重新打字 ✓
- `?static` 模式：无动画，静态终值（符合预期）✓
- 无页面错误 ✓
